# Huckbot5000

Gap-fill English glosses for Chinese office titles that still lack a
publishable translation in our packs. Candidates are generated (procedural
rules or LLM), checked against known Hucker / CBDB-`(Hucker)` wording, and
only reviewed non-matching rows ship as `source: 'Huckbot5000'`. See
[leaf-writer/docs/huckbot5000-planning.md](../../leaf-writer/docs/huckbot5000-planning.md)
for the feasibility study, the numbers behind each design choice, and the
rights-hygiene rationale this directory exists to satisfy. Current status and queue
sizes:
[leaf-writer/docs/huckbot5000-integration-plan.md](../../leaf-writer/docs/huckbot5000-integration-plan.md).
This README documents the mechanics of the pipeline; those docs are the
source of truth for *why* and *where we are*.

Two independent artifacts live here, built by different scripts:

- **`packs/huckbot5000/lexicon.ndjson`** (`npm run compile:huckbot5000`) --
  a mined character-n-gram morpheme lexicon, a statistical fact about
  Hucker's vocabulary. Shippable in principle (pending the Legal note),
  since it's a compact derived table, not prose.
- **`packs/huckbot5000/translations.ndjson`** (this workflow) -- full
  office-title glosses generated by GPT-4o *or* by procedural rules,
  reviewed row by row before anything reaches the pack. This is the
  higher-risk artifact and the one the collision filter and human review
  below exist to gate.
- **`packs/huckbot5000-insiders/translations.ndjson`** -- local **collision
  archive**: candidates that matched known Hucker / CBDB-`(Hucker)` text
  (`source: 'Hucker'`). Kept for provenance/audit only; gitignored; not for
  redistribution. See step 5 below.

## Prerequisites

```bash
npm run reconcile:norbert-offices   # dates + office concordance + crosswalks
# Needs locally:
#   skunkworks/scripts/out/hucker_entries.ndjson   (OCR corpus)
#   .upstream/cbdb.sqlite3                        (full CBDB; npm run fetch:upstream)
```

Never `--resume` against `candidates.pre-reconcile.ndjson` (old headword-only
keys from the killed first run).

## Review workflow

The shape is the same reviewed-boundary pattern as `noble-titles/`: audit
script -> decision table -> compile only accepted rows -> build reads only
the compiled include, never the raw source.

1. **Generate candidates.** Procedural rows (place+suffix, parentOf) are
   written first; remaining targets go to GPT-4o.

   ```bash
   # Preview split / prompts (no API spend)
   npm run generate:huckbot5000 -- --dry-run

   # Rewrite procedural only (after rule changes; no API key)
   npm run generate:huckbot5000 -- --procedural-only

   # Small LLM pilot
   OPENAI_API_KEY=... npm run generate:huckbot5000 -- --sample 100

   # Full run (keeps existing procedural/LLM rows; keys on zh+dynasty)
   OPENAI_API_KEY=... npm run generate:huckbot5000 -- --resume
   ```

   Targets are period-aware CBDB untranslated `(headword, dynasty)` groups
   plus dated Norbert-only offices with no concordance link. Skipped before
   spend: Hucker OCR period coverage, and CBDB `(Hucker)`-tagged headwords
   (those glosses come from the user's CBDB download — we don't regenerate
   them). Writes `packs/huckbot5000/candidates.ndjson` (gitignored staging).

2. **Run the collision filter.** `npm run audit:huckbot5000`. Checks every
   candidate against Hucker's actual text from **two sources**: the local
   OCR-extracted dictionary corpus, and CBDB's own `(Hucker)`-tagged office
   translations read directly from the full upstream sqlite
   (`.upstream/cbdb.sqlite3`, fetched by `npm run fetch:upstream` if not
   already present -- ~550MB, so the check degrades to OCR-only with a
   warning if it's missing rather than failing). The second source matters:
   only 22% of CBDB's Hucker-tagged headwords exist in the OCR corpus, the
   rest being longer compound institutional titles Hucker's own dictionary
   doesn't headword separately. Checks for exact, near-verbatim (high string
   similarity or full/subset content-word overlap), stylistic-tell
   (Hucker's own stock hedge phrases, e.g. "meaning and derivation not
   clear") collisions, and **transliteration punts** (romanization of the
   Chinese headword plus a generic noun, e.g. "Pingshun Office"). Writes
   `reports/huckbot5000-candidate-review.csv`. This step never changes a
   pack or the include file.
3. **Review.** Open the CSV. `collisionFlag`/`collisionDetail` explain any
   automatic rejection; `status` is the decision column
   (`accepted`/`deferred`/`rejected`). Rows the filter already flagged are
   pre-filled `rejected` -- **the hard gate: a row with
   `collisionFlag !== 'none'` can never enter the shippable pack, even if a
   reviewer marks it `accepted`** (enforced again at compile time). Only
   mark `accepted` for a row you've read and judge to be a genuine,
   independently-composed scholarly gloss.
4. **Compile the includes.** `npm run compile:huckbot5000-include` reads
   your reviewed CSV and writes two files:
   - `huckbot5000/approved-include.ndjson` — accepted rows only,
     collision-gated (publishable boundary).
   - `huckbot5000/insiders-include.ndjson` — every row with
     `collisionFlag !== 'none'` (local collision archive; gitignored).
     Dedupes both by `(zh, dynasty)`. Re-running `audit:huckbot5000` after
     this reflects `approved:<id>` status back into a fresh CSV.
5. **Build the packs.**
   - `npm run compile:huckbot5000-translations` →
     `packs/huckbot5000/translations.ndjson`, every row tagged
     `source: 'Huckbot5000'`.
   - `npm run compile:huckbot5000-insiders` →
     `packs/huckbot5000-insiders/translations.ndjson`, every row tagged
     `source: 'Hucker'`, license `local-use-only-do-not-redistribute`.
     Collision archive for audit only — never add to a release tarball.

## Files

- `lib.mjs` -- shared helpers: Hucker corpus loader, lexicon mining,
  retrieval index, `detectCollision()`, `detectTransliterationPunt()`
  (unit-tested in `lib.test.mjs`).
- `resolveTargets.mjs` -- period-aware, concordance-aware target resolution
  (unit-tested in `resolveTargets.test.mjs`). When a Hucker index is
  available, targets whose headword+dynasty are already covered by Hucker's
  own period span are dropped before procedural/LLM work. Headwords that
  appear in CBDB's `(Hucker)`-tagged OFFICE_CODES are also skipped — LJB
  displays those from the user's CBDB; Huckbot fills true blanks only.
  Hucker's gloss is never copied into *our* redistributable packs.
- `proceduralPlaceSuffix.mjs` -- place+suffix compound detection and template
  translation (unit-tested in `proceduralPlaceSuffix.test.mjs`). Applied
  automatically in `generate.mjs` before any LLM calls. Place stems are
  concatenated toneless pinyin (`遼東` → `Liaodong`; `豫州` → `Yuzhou`).
  `X州刺史` is allowed (stem may end in 州); dynasty-prefixed stems, 左/右
  qualifiers, and embedded office titles (`郡守刺史`) are rejected. Known
  false positives (e.g. `遷安固太守`) are blocklisted. Re-run with
  `--procedural-only` after rule changes (no API key needed).
- `proceduralParentOf.mjs` -- compound offices via Norbert `parentOf` links
  (unit-tested in `proceduralParentOf.test.mjs`). v1 allowlists parents
  `太子` / `公主` / `親王` and composes `{Remainder} of the {Parent}` when
  the remainder already has an office gloss. CBDB office-type-tree
  `parentOf` edges are not used. Applied after place+suffix, before LLM.
- `compile.mjs` -- morpheme lexicon compiler (unrelated to the translation
  workflow above; see the two-artifact note).
- `generate.mjs` -- GPT-4o + retrieval candidate generator. Loads Hucker for
  retrieval *and* for period/CBDB-headword coverage skip, then splits
  remaining targets into procedural (place+suffix, parentOf) vs LLM.
- `audit.mjs` -- collision filter + transliteration-punt filter + review CSV
  writer.
- `compileTranslations.mjs` -- approved-include -> shippable pack
  (`source: 'Huckbot5000'`).
- `compileInsidersTranslations.mjs` -- insiders-include -> local collision
  archive (`source: 'Hucker'`; not for redistribution).
- `../scripts/compile-huckbot5000-include.mjs` -- reviewed CSV -> approved
  include *and* insiders include (lives in `scripts/` alongside
  `compile-noble-title-include.mjs`, the pattern it mirrors).
- Related Norbert modules: `../norbert/deriveOfficeDates.mjs`,
  `officeConcordance.mjs`, `huckerOfficeContinuity.mjs`,
  `reconcileOffices.mjs` (`npm run reconcile:norbert-offices`).

## Guarantees

- An empty or missing `approved-include.ndjson` compiles to an empty pack.
- No script here ever reads `candidates.ndjson` or the raw Hucker corpus
  from `compileTranslations.mjs` -- only the reviewed include.
- A candidate whose content words match Hucker's own gloss for the same
  headword, or that reproduces one of Hucker's stock hedge phrases, is
  rejected regardless of human review status.
- A candidate that only romanizes the Chinese headword (e.g. 平隼案 →
  "Pingshun Office") is rejected as a transliteration punt.
- `license: 'internal-pending-review'` on every manifest until
  huckbot5000-planning.md's Legal note (EU *sui generis* database right, US
  copyright) is resolved -- do not redistribute publicly before then.
- The collision archive (`huckbot5000-insiders`) is for local provenance/audit
  only and must not appear in public releases.
